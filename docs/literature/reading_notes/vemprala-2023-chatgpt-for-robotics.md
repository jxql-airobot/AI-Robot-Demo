# 论文阅读笔记

## 基本信息

标题：

英文：ChatGPT for Robotics: Design Principles and Model Abilities

中文：ChatGPT 用于机器人：设计原则与模型能力

作者：Sai Vemprala, Rogerio Bonatti, Arthur Bucker, Ashish Kapoor（Microsoft）

年份：2023

来源：arXiv 2306.17582

链接：https://arxiv.org/abs/2306.17582

---

## 研究背景

大语言模型能对话、能写代码，但怎么让它真正控制机器人？直接问 ChatGPT
"怎么飞过去"没用，它需要知道机器人有哪些可用能力、动作接口长什么样。
论文是微软的一篇实验研究：总结一套提示工程设计原则，配合一个高层函数库，
让 ChatGPT 在多种机器人任务上"写代码、调函数"地干活。

---

## 核心思想

输入：任务自然语言描述 + 机器人函数库（高层 API 清单）+ 对话历史

↓

方法：几条提示设计原则——任务分解、告诉模型可用的函数库、让它输出代码
调用高层函数、用闭环对话根据执行反馈修正；模型负责"编排"，函数库负责
"执行细节"

↓

输出：可运行的机器人控制代码/函数调用序列

---

## 系统架构

```
任务描述 + 函数库文档
  ↓
ChatGPT（提示工程 + 代码生成）
  ↓
高层函数调用（飞往坐标、抓取、导航…）
  ↓
执行 + 反馈回到对话
  ↓
闭环修正
```

---

## 技术方法

- 使用什么模型：OpenAI ChatGPT（GPT-3.5/GPT-4 时代）
- 使用什么Agent机制：对话式闭环，模型生成代码而不是动作序列
- 是否使用RAG：否（函数库直接写在提示里）
- 是否使用工具调用：是，通过高层函数库调用机器人能力

---

## 实验设计

机器人平台：AirSim 无人机仿真 + 真实无人机、操作任务仿真

实验环境：逻辑/几何/数学推理任务、无人机导航（圆形、割草机式巡检）、
操作任务（pick and place 类）、具身 agent 场景

任务：从"理解任务"到"生成可执行代码"

评价指标：任务能否完成、代码正确性、人工交互体验

实验结果：ChatGPT 在多项任务上能靠自然语言交互完成，且能写复杂巡检代码；
作者同时开源 PromptCraft 平台（提示词社区）和 AirSim-ChatGPT 仿真环境。

---

## 与AI-Robot-Demo关系

相同点：函数库思想与项目动作契约高度一致——都是"先把机器人能力列给模型，
模型只能在这些能力里选"；闭环对话也对应项目的多轮上下文。

不同点：这篇让模型直接生成代码，项目让模型生成 JSON 动作契约，再由
command_schema 映射成 RAPID 命令。JSON 契约比代码更好校验、更好记录、
更不容易产生不可控副作用。

可以借鉴："把函数库文档写进提示词"的实践细节，正是我们 DeepSeek
规划器提示词里工具描述部分的来源。

不适合采用：让 LLM 直接生成完整控制代码——工业上无法逐行审计，且代码
错误难回退。

---

## 个人理解

这篇像"LLM 控制机器人"的实践手册，验证了函数库 + 提示工程这条路可行。
我们的系统相当于把它的"函数库"升级成了带 schema 校验的动作契约，把
"代码输出"换成了"JSON 计划输出"。读它最大的价值是确认方向：让模型
做编排，让系统做执行。
