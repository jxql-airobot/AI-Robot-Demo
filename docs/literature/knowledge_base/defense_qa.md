# 答辩高频问题与回答要点

回答原则：先给结论，再讲依据，最后落到自己的系统；每个问题都对应可查的
论文编号和实验数据。

---

## Q1：你的 Agent 设计参考了什么？

要点：ReAct [15] 的推理-行动-观察闭环是思想来源；Agent 综述 [16] 提供
Planning/Memory/Tool use 框架；具体到机器人，SayCan [6] 说明语言模型
必须受技能约束。

落点：我们的 Agent 不是简单调 LLM，而是"理解-规划-工具调用-反馈"的执行
管理模块，且规划器可插拔（LLM/规则）。

---

## Q2：LLM 输出不可控，怎么保证安全？

要点：动作契约白名单（move_home/joint_move/linear_move/...）+ 安全序列
规范化 + 可达性校验（3.4.4、4.4.2）；SayCan [6] 用价值函数做可行性约束
是同类思路。

落点：LLM 只负责出计划，系统负责校验和执行，链条"LLM 输出→动作契约→
安全约束→Robot Interface→机器人执行"全程可审计。

---

## Q3：为什么需要 RAG？

要点：RAG [19] 论证参数化记忆难溯源、难更新；工业知识（单位换算、错误码、
操作规范）不在通用模型参数里。

落点：实验 5.3——语义召回 0%→100%，知识问答参数命中 0~2→3~4，引用率
100%。

---

## Q4：和 PaLM-E / RT-2 的区别？

要点：它们是端到端（多模态 token / 动作 token），强泛化但难审计；
我们是模块化系统，规划与执行解耦，安全约束显式。

落点：工业验收要求可解释、可约束、可回退，所以我们选软件工程路线；
它们代表未来方向（第 6 章展望）。

---

## Q5：为什么不用 ROS2 直接做系统？

要点：ROS2 [10] 提供节点化、松耦合思想，我们借鉴了它；但 ABB 工业机器人
链路需要 TCP + RAPID，和 ROS2 生态不直接兼容。

落点：Robot Interface 把"智能规划层"和"执行后端"解耦，Gazebo 和
RobotStudio 都能接，这才是借鉴 ROS2 思想的具体体现。

---

## Q6：创新点是什么？

要点：① LLM Agent 工业任务规划分层架构；② 规划/安全/执行三层解耦 +
JSON 动作契约；③ RAG 工业知识增强；④ 后端插件化（Gazebo/RobotStudio）；
⑤ 在 ABB RobotStudio 仿真平台与 IRC5 虚拟控制器上完成闭环验证。

落点：不是"接了 DeepSeek"，而是"把 LLM 能力变成可靠可执行系统的软件
工程方法"。

---

## Q7：局限是什么？

要点：虚拟控制器环境、未上物理机器人；任务集范围有限；LLM 偶发空计划和
动作选择偏差；未现场部署（5.5.4、6.2）。

落点：这些局限对应第 6 章展望的四个方向，是后续工作起点。

---

## Q8：未来做什么？

要点：视觉语言机器人（PaLM-E [8] 多模态）、Robot Agent 自主化
（Inner Monologue [7] 反馈再规划）、多智能体协同、结合 PLC/MES 的工业
智能系统。

落点：每个方向都有具体论文依据，不是空谈。

---

## 一句话技术路线（复试用）

"我们做一个基于大语言模型智能体的工业机器人任务规划系统：LLM 把自然语言
任务理解成可解释计划（ReAct 思想），RAG 注入工业知识，动作契约和安全
约束层把计划转成可执行指令，Robot Interface 解耦后端，最后在 ABB
RobotStudio 与 IRC5 虚拟控制器上闭环验证。"
